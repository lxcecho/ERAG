# 本地部署调试手册

> 本手册面向开发者本地启动调试。推荐做法：**中间件用 Docker 起，后端/前端用 IDE 本地跑**，便于断点调试。
>
> 一键容器化部署（含 backend/frontend）请参考根目录 [README.md](../README.md) 的「快速开始」章节。
>
> IDEA 加载 `deploy/.env` 启动后端的详细配置见 [IDEA启动指南.md](IDEA启动指南.md)。

---

## 一、组件依赖总览

本地调试共四层，按下表准备。**MySQL 与 Milvus 为硬依赖**；Elasticsearch / RabbitMQ / Redis 三者均有**降级开关**，可按调试目标按需启用。

| 层 | 组件 | 端口 | 启动方式 | 是否必须 | 说明 |
|----|------|------|----------|----------|------|
| **基础设施** | MySQL 8.0 | 3306 | Docker | ✅ 必须 | 业务数据（用户/知识库/聊天/日志/运维） |
| | etcd | 2379 | Docker | ✅ 必须 | **Milvus 的元数据依赖**，不直接使用 |
| | milvus-minio | —（仅内部网络） | Docker | ✅ 必须 | **Milvus 的对象存储依赖**，不对外暴露端口 |
| | Milvus 2.4 | 19530 | Docker | ✅ 必须 | 向量检索（RAG 召回） |
| | Elasticsearch 8.11 | 9200 | Docker | ⚡ 可选 | 混合检索词法路（BM25）；`HYBRID_ENABLED=false` 可跳过 |
| | RabbitMQ 3.13 | 5672 / 15672 | Docker | ⚡ 可选 | 文档解析任务队列；`KB_PARSE_MQ_ENABLED=false` 降级 @Async |
| | Redis 7.4 | 6379 | Docker | ⚡ 可选 | 全局缓存（Prompt/KB/统计/检索）；`SPRING_CACHE_TYPE=none` 直通 |
| | MinIO（应用存储） | 9000 / 9001 | Docker | ⚡ 可选 | 应用文件存储；`KB_STORAGE_TYPE=local` 时存本地无需启动 |
| **应用服务** | 后端 knowledge-admin | 8080 | IDE / mvn | ✅ 必须 | Spring Boot，context-path=/api |
| | 前端 Vite dev | 5173 | npm run dev | ✅ 必须 | Vue3 开发服务器 |
| **外部 API** | LLM（阿里云百炼 / DeepSeek 等） | — | 联网 + API Key | ✅ 必须 | RAG 问答与 Agent 统一走 LangChain4j（`LLM_BASE_URL`） |
| | Embedding（Ollama bge-m3） | — | 本地服务 | ✅ 必须 | 文档/问题向量化（入库时） |

> **要点 1**：etcd 和 milvus-minio 是 **Milvus standalone 的硬依赖**，随 `milvus` 自动启动（`depends_on`），不直接使用。
> **要点 2**：Elasticsearch / RabbitMQ / Redis 是**可选增强组件**，各有降级开关，未启动时对应功能自动降级（见第四节）。
> **要点 3**：MinIO 在本手册中有两个实例——`milvus-minio`（Milvus 内部，无端口）与 `minio`（应用文件存储，9000/9001）。本地用 `KB_STORAGE_TYPE=local` 时后者可省略。
> **要点 4**：推荐本地开发使用 **Ollama bge-m3:latest** 作为向量模型（1024 维，免费，本地运行），**阿里云百炼 qwen3.5-27b** 作为 LLM（通义千问）。

### 组件依赖关系

```
应用层        后端 (8080) ──► MySQL(3306)              业务数据（含运维表）
              后端 (8080) ──► Milvus(19530) ──► etcd(2379)        Milvus 元数据
              │                              └► milvus-minio     Milvus 对象存储
              后端 (8080) ──► Elasticsearch(9200)    混合检索词法路（可选）
              后端 (8080) ──► RabbitMQ(5672)         文档解析任务队列（可选）
              后端 (8080) ──► Redis(6379)            全局缓存（可选）
              后端 (8080) ──► Ollama(11434)          本地向量模型（bge-m3）
              后端 (8080) ──► LLM API (阿里云百炼)   联网 LLM 生成
              前端 (5173) ──► 后端 (8080)  (Vite 代理 /api)
```

### 中间件降级矩阵（重要）

| 组件 | 降级开关（环境变量） | 关闭后影响 | 适用场景 |
|------|---------------------|-----------|----------|
| Elasticsearch | `HYBRID_ENABLED=false` 或 `ES_ENABLED=false` | 退化为纯向量检索（无 BM25 词法路） | 只验证 RAG 基础问答 |
| RabbitMQ | `KB_PARSE_MQ_ENABLED=false` | 文档解析走 @Async 事件（无重试/死信/补偿） | 不关心 MQ 可靠性 |
| Redis | `SPRING_CACHE_TYPE=none` | 缓存直通 DB（每次回源，性能下降但不报错） | 本机无 Redis / 不关心缓存 |
| MinIO（应用） | `KB_STORAGE_TYPE=local` | 上传文件存本地 `./data/files` | 本地开发默认 |
| Elasticsearch/MQ/Redis | 全部设为 false/none | 仅需 MySQL + Milvus 即可跑通核心 RAG | 最小化环境 |

> 三个可选组件全部关闭时，只需 **MySQL + Milvus** 即可跑通核心 RAG 流程。

## 二、环境前置要求

| 软件 | 最低版本 | 验证命令 |
|------|----------|----------|
| Docker Desktop | 24.x | `docker --version` |
| Docker Compose | v2.x | `docker compose version` |
| JDK | 17（项目编译目标） | `java -version` |
| Maven | 3.8+ | `mvn -v` |
| Node.js | 18+ | `node -v` |
| npm | 9+ | `npm -v` |
| Ollama（向量模型） | 最新 | `ollama --version` |

> 后端编译目标为 Java 17，用 JDK 17/21 均可运行。

### 安装 Ollama（推荐本地向量模型）

```powershell
# 1. 下载安装包：https://ollama.com/download/windows
# 2. 拉取 bge-m3:latest（1024 维，中文优化）
ollama pull bge-m3:latest

# 3. 验证
ollama list

# 4. 测试 Embedding
curl http://localhost:11434/api/embeddings -d '{
  "model": "bge-m3:latest",
  "prompt": "你好，世界"
}'
```

> Ollama 默认运行在 `http://localhost:11434`，LangChain4j OpenAI 兼容协议可直接调用。

### Linux 前置（仅启用 Elasticsearch 时）

ES 8.x 要求宿主机 `vm.max_map_count ≥ 262144`，**首次启用 ES 前必须执行**（Windows Docker Desktop 通常无需，Linux 宿主机必须）：

```bash
sudo sysctl -w vm.max_map_count=262144
# 永久生效：echo 'vm.max_map_count=262144' | sudo tee -a /etc/sysctl.conf
```

## 三、启动顺序（推荐流程）

### 第 1 步：用 Docker 起中间件

在项目根目录执行（**只起中间件，不起 backend/frontend**，后两者留给本地 IDE 调试）。

**全量启动（推荐，体验完整功能）**：

```powershell
docker compose up -d mysql milvus elasticsearch rabbitmq redis minio
```

> etcd / milvus-minio / minio-init 会随 `milvus` / `minio` 的 `depends_on` 自动启动，无需显式列出。

验证：

```powershell
docker compose ps
```

各容器均为 `running`，MySQL 显示 `healthy` 即可。Milvus 启动较慢（约 30s~1min），ES 次之（约 40s）。

**最小启动（仅验证登录 / 知识库 CRUD）**：

```powershell
docker compose up -d mysql
```

**RAG 问答（向量检索，不含混合检索/MQ/缓存）**：

```powershell
docker compose up -d mysql milvus
```

### 第 2 步：准备数据库表

- **首次启动** MySQL 容器时，`deploy/init.sql` 会自动执行建库建表 + 种子数据（默认账号 `admin` / `123456`）。
- **已存在数据卷**（之前起过该容器）时，`init.sql` 不会重复执行，需手动导入：

  ```powershell
  Get-Content deploy\init.sql -Raw | docker exec -i erag-mysql mysql -uroot -proot123 knowledge_ai
  ```

  > 容器名以 `docker compose ps` 实际输出为准（默认 `erag-mysql`）。

### 第 3 步：启动 Ollama（向量模型）

```powershell
# 检查是否已启动
ollama list

# 若未拉取 bge-m3:latest，执行
ollama pull bge-m3:latest

# Ollama 默认后台运行，无需额外启动
```

### 第 4 步：配置环境变量（关键，否则 AI 功能失败）

后端 `application.yml` 中 API Key 默认为空，必须通过环境变量注入。

**方式 A —— IDEA Run Configuration（推荐）**

`Run → Edit Configurations → Environment variables` 填入：

```
LLM_BASE_URL=https://api.deepseek.com/v1  # 任意 OpenAI 兼容端点
LLM_API_KEY=sk-xxx
EMBEDDING_BASE_URL=http://localhost:11434/v1
EMBEDDING_MODEL=bge-m3:latest
DB_HOST=localhost
DB_PASSWORD=root123
KB_STORAGE_TYPE=local
```

**方式 B —— 命令行启动**

```powershell
$env:LLM_BASE_URL="https://api.deepseek.com/v1"
$env:LLM_API_KEY="sk-xxx"
$env:EMBEDDING_BASE_URL="http://localhost:11434/v1"
$env:EMBEDDING_MODEL="bge-m3:latest"
$env:DB_HOST="localhost"
$env:DB_PASSWORD="root123"
$env:KB_STORAGE_TYPE="local"
mvn -f knowledge-backend\pom.xml -pl knowledge-admin spring-boot:run
```

> **三个配置用途**：
> - **LLM_BASE_URL / LLM_API_KEY**：RAG 问答生成 + Agent 推理统一走 LangChain4j（默认阿里云百炼，OpenAI 兼容协议）
> - **EMBEDDING_BASE_URL / EMBEDDING_MODEL**：本地 Ollama bge-m3:latest（1024 维，免费）
> - **DB_PASSWORD**：Docker MySQL 密码 root123（见第四节「坑 1」）

### 第 5 步：启动后端（IDE 调试）

在 IDEA 中运行 [KnowledgeApplication.java](../knowledge-backend/knowledge-admin/src/main/java/com/knowledge/KnowledgeApplication.java)，默认激活 `dev` profile。

验证：访问 http://localhost:8080/api/doc.html 出现 Knife4j 接口文档即成功。

### 第 6 步：启动前端

```powershell
cd knowledge-frontend
npm install        # 首次需要
npm run dev
```

验证：访问 http://localhost:5173 ，使用 `admin` / `123456` 登录。

## 四、必须注意的「坑」

### 1. MySQL 密码 ⚠️

- `docker-compose.yml` 中 MySQL root 密码默认 `root123`
- 后端 `application-dev.yml` 中 `DB_PASSWORD` 默认已是 `root123`（`${DB_PASSWORD:root123}`），与 Docker 一致

**本地连 Docker 的 MySQL 时无需覆盖**；若你改过 `.env` 中 `MYSQL_ROOT_PASSWORD`，需同步把 `DB_PASSWORD` 环境变量改为相同值。

### 2. DB_HOST 不要用服务名

`.env.example` 中 `DB_HOST=mysql` 是**容器内网络**才用的服务名。本地 IDE 调试时后端跑在宿主机，应使用默认值 `localhost`（`application-dev.yml` 已默认 `localhost`，无需覆盖）。

同理 `MILVUS_HOST` / `RABBITMQ_HOST` / `REDIS_HOST` / `ES_URIS` 本地调试均用 `localhost`，不要用容器服务名。

### 3. Milvus / ES 启动慢，后端可能启动失败

Milvus（约 30s~1min）与 ES（约 40s）就绪前启动后端会因连接失败而报错。处理方式：
- 等容器 `healthy` 后再启动后端（`docker compose ps` 看状态）
- 或后端启动失败后直接重试（Spring Boot 不会自动重连，需手动重启）

### 4. Embedding 维度必须与 Milvus 一致

默认 `bge-m3:latest` 输出 1024 维，Milvus collection 也是 1024 维。**若更换 Embedding 模型**，维度不一致会报错，需同步修改：

```yaml
ai:
  embedding:
    dimension: 1024      # 改为新模型维度
  milvus:
    dimension: 1024      # 同步修改
```

并删除旧 collection 重建（首次入库会自动创建 collection）。

### 5. 本地文件存储位置

默认 `KB_STORAGE_TYPE=local`，上传文档存储于 `knowledge-admin/data/files`（相对启动目录）。若本地也想用 MinIO：

```
KB_STORAGE_TYPE=minio
KB_STORAGE_MINIO_ENDPOINT=http://localhost:9000
KB_STORAGE_MINIO_ACCESS_KEY=minioadmin
KB_STORAGE_MINIO_SECRET_KEY=minioadmin123
KB_STORAGE_MINIO_BUCKET=knowledge-files
```

> 注意：MinIO bucket 需提前创建，或由后端首次启动时自动创建（见 `MinioStorageService`）。

### 6. 三个可选组件的降级配置 ⚡

不想启动 ES / RabbitMQ / Redis 时，在环境变量中关闭对应开关，后端会自动降级：

```powershell
# 不启用 Elasticsearch（纯向量检索）
$env:HYBRID_ENABLED="false"
$env:ES_ENABLED="false"

# 不启用 RabbitMQ（文档解析走 @Async 事件）
$env:KB_PARSE_MQ_ENABLED="false"

# 不启用 Redis（缓存直通 DB）
$env:SPRING_CACHE_TYPE="none"
```

> **Redis 降级注意**：`spring.cache.type=none` 时 `RedisCacheManager` 与 `CacheService` 不装配，Lettuce 连接 lazy 不初始化，故未启 Redis 容器也不会报错。但 Agent 记忆中心的 `VectorMemory`（独立 Milvus 集合）不受影响。

### 7. Sentinel Dashboard（可选）

Sentinel 限流/熔断走**本地 JSON 规则文件**兜底（`sentinel-flow-rules.json` / `sentinel-degrade-rules.json`），不启动 Dashboard 不影响应用。如需可视化推规则：

```powershell
java -jar sentinel-dashboard-1.8.8.jar --server.port=8858
# 默认账号 sentinel/sentinel，应用配置 SENTINEL_DASHBOARD=localhost:8858
```

### 8. @Transactional 循环依赖修复

若启动时遇到 `UnsatisfiedDependencyException` 报循环依赖，需检查 `KbParseTaskServiceImpl` 和 `KbDocumentServiceImpl` 是否已使用**构造器参数级 `@Lazy`** 打破循环（`KbParseTaskServiceImpl` 通过构造器注入 `KbDocumentService`，后者对前者加 `@Lazy`，启动期推迟实例化即可解除循环）。

## 五、最小启动集（分阶段调试）

不必一开始就拉起全部组件，可按调试目标分阶段：

| 调试目标 | 需启动的中间件 | 需要的 API Key | 降级开关 |
|----------|--------------|----------------|----------|
| 登录 / 用户角色 / 菜单 | MySQL | ❌ | — |
| 知识库 CRUD / 成员管理 / 操作日志 | MySQL | ❌ | — |
| Prompt 模板管理 | MySQL + Redis（可选） | ❌ | `SPRING_CACHE_TYPE=none` |
| AI 调用日志 / 统计 / 运维看板 | MySQL | ❌ | — |
| 文档上传 + 异步解析 + 向量化入库 | MySQL + Milvus | ✅ Embedding | `KB_PARSE_MQ_ENABLED=false` |
| 文档解析 MQ 可靠性（重试/死信/补偿） | MySQL + Milvus + RabbitMQ | ✅ Embedding | — |
| RAG 问答 / SSE 流式 / 多轮对话 | MySQL + Milvus | ✅ LLM + Embedding | — |
| 混合检索（向量+BM25+RRF+ 精排） | MySQL + Milvus + Elasticsearch | ✅ LLM + Embedding | `RERANK_TYPE=http` 需额外配 |
| Agent 任务 / Workflow 流程 | MySQL + Milvus | ✅ LLM + Embedding | — |
| AI 运维中心（链路追踪/告警） | MySQL + Milvus | ✅ LLM | — |

> 例如：只想验证登录和权限隔离，`docker compose up -d mysql` 起一个 MySQL 即可，无需配 API Key。

## 六、停止与清理

### 停止中间件（保留数据）

```powershell
docker compose stop
```

### 停止并删除容器（保留数据卷）

```powershell
docker compose down
```

### 彻底清除数据（⚠️ 谨慎，会删除所有业务/向量数据）

```powershell
docker compose down -v
```

## 七、常用命令速查

```powershell
# === 中间件 ===
docker compose up -d mysql milvus elasticsearch rabbitmq redis minio  # 全量起中间件
docker compose up -d mysql                                              # 最小起
docker compose ps                                                       # 查看状态
docker compose logs -f milvus                                           # 看 Milvus 日志
docker compose logs -f elasticsearch                                    # 看 ES 日志
docker compose stop                                                     # 停止全部

# === Ollama ===
ollama pull bge-m3:latest        # 拉取向量模型
ollama list                      # 列出已安装包
ollama stop bge-m3:latest        # 停止模型
ollama rm bge-m3:latest          # 删除模型

# === 后端 ===
mvn -f knowledge-backend\pom.xml clean compile -DskipTests              # 编译
mvn -f knowledge-backend\pom.xml -pl knowledge-admin spring-boot:run    # 启动

# === 前端 ===
cd knowledge-frontend
npm install
npm run dev        # 开发 http://localhost:5173
npm run build      # 生产构建

# === 数据库 ===
docker exec -it erag-mysql mysql -uroot -proot123 knowledge_ai          # 进 MySQL
Get-Content deploy\init.sql -Raw | docker exec -i erag-mysql mysql -uroot -proot123 knowledge_ai  # 导入脚本

# === 中间件控制台 ===
docker exec -it erag-rabbitmq rabbitmqctl list_queues                   # 查看 RabbitMQ 队列
docker exec -it erag-redis redis-cli                                    # 进 Redis CLI
curl http://localhost:9200/_cluster/health                              # ES 健康检查
```

## 九、故障排查 Checklist

| 现象 | 排查方向 |
|------|----------|
| 后端启动报 `Communications link failure` | MySQL 未起 / `DB_PASSWORD` 不是 `root123` / 端口冲突 |
| 后端启动报 Milvus 连接超时 | Milvus 未就绪，等 1 分钟后重启后端 |
| 后端启动报 ES 连接失败 | ES 未就绪 / 不需要 ES 时设 `ES_ENABLED=false` |
| 后端启动报 RabbitMQ 连接失败 | RabbitMQ 未起 / 不需要 MQ 时设 `KB_PARSE_MQ_ENABLED=false` |
| 后端启动报 Redis 连接失败 | Redis 未起 / 不需要缓存时设 `SPRING_CACHE_TYPE=none` |
| 后端启动报 ES `max virtual memory areas` | 未执行 `sysctl -w vm.max_map_count=262144`（Linux） |
| 后端启动报 UnsatisfiedDependencyException 循环依赖 | 检查 `KbParseTaskServiceImpl` 是否用构造器参数级 `@Lazy` |
| Agent 启动报 401 / 模型调用失败 | `LLM_API_KEY` 未配 / Key 失效 |
| 上传文档后任务一直「处理中」 | `EMBEDDING_BASE_URL` 未配 / Ollama 未启动 / Embedding 服务不可达，看后端日志 |
| RAG 问答返回空或报错 | `LLM_API_KEY` 未配 / 知识库无已成功解析的文档 / 相似度阈值过高 |
| 文档上传 403 | 当前用户对目标知识库无 `editor` 权限，去成员管理加权限 |
| SSE 流式无输出 | `/ai/stream` 鉴权失败，确认 token 通过 query 参数传递 |
| 前端登录 401 | 后端未起 / JWT_SECRET 不一致 / 账号密码错误 |
| 运维看板指标全为 0 | 对应功能未实际调用过（指标按调用累计）；链路追踪检查 `OPS_TRACE_ENABLED` |
| task 状态 2 但 doc 状态 1 | 状态同步修复后已解决，重新触发解析即可 |
